# Votes are intra-org: each Vault's own wallets veto, fast-track and change settings

Cross-org Member votes are gone. A Vault's whitelisted wallets vote, one wallet one vote, with the voter set snapshotted at proposal. More than 50% of the wallets other than the requester can veto a Queued request; more than 50% of all wallets can fast-track it to the Floor, unfreeze, change wallets or loosen settings (48h timelock). Any single wallet can freeze. A Vault needs at least 3 wallets, because with 2 a single hacked wallet blocks every honest veto. No vote chooses a destination: migration only goes to the Recovery vault fixed at onboarding. We rejected role-weighted votes as unnecessary (higher-ups hold wallets like everyone else) and single-wallet veto as a griefing path. The cost: the guarantee holds only while fewer than half the wallets are compromised, and only if those wallets don't share one signer.
