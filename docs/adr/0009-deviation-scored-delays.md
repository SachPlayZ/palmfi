# The Sentinel sets a delay from a deterministic deviation score instead of CLEAR/HOLD

The Sentinel scores each Queued request as surprisal in bits (amount vs robust log-amount baseline, destination frequency, hour of day, Poisson velocity, config flags), at wallet and Vault scope, and reports `delay = clamp(Floor * 2^(S/k), Floor, MaxDelay)`, or FLAG above `S_flag`. The request executes after the delay unless a majority vetoes (optimistic veto). The baseline lives onchain and learns only from executed, un-vetoed requests, with a per-day drift cap; the coarse onboarding profile (ADR-0007) seeds it. No randomness, because DON consensus needs determinism. When CRE is silent the delay is MaxDelay, and above the Hard cap it is at least CapDelay. We rejected the v1 CLEAR/HOLD table, which needed per-org approvers. The cost is that silence favours the requester, so delays must outlast how fast honest voters respond.
